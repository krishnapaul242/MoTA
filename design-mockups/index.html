MoTA UI redesign · draft for review

Static mockups with sample data. Use the bar at the top to switch pages and themes. Nothing here is wired to a device.

What is wrong today (all four pages)

  • No hierarchy. Every button uses the primary blue style, so a page shows 6–20 equally loud buttons. Destructive actions (Uninstall, Clear data, Reboot) look the same as Launch.
  • Not VS Code-like. 27 px headings, 28 px padding and large cards read as a web dashboard, not as part of the editor. There are no icons.
  • Messages and output are dumped as text: a status line at the top, a “Command output” card always pinned to the bottom, and errors as raw pre blocks.
  • Pages redraw themselves completely (Install re-renders all HTML on every progress tick), so focus and typed input get lost.

Claude bar, at the bottom of every page

  • Ask Claude in plain words: “install the debug build on these phones and check the cart”. It acts through MoTA's own tools (screenshot, tap, install, logcat, shell…) and shows each step as one line with its result.
  • Runs as a Claude Agent SDK session inside the extension using your Claude Code login. The same tools can also be turned on, as an opt-in setting, for Claude Code or Claude Desktop.
  • Permissions: Ask once per task (default: approve a plan, then small steps run freely; data loss asks again), Ask only for data loss, or Read-only.
  • Token limit per task with typical sizes: 5–15K quick action, 15–40K one diagnosis, 60–150K writing a flow, 200K+ exploring.
  • The scope chip limits which devices Claude may touch. It follows your selection, or the device you're viewing.
  • The terminal icon switches the same panel to the ADB console.

Device controls

Live screen + tools in tabs

  • Today: no live screen; tap/swipe needs typed X/Y numbers; 5 tabs of uniform buttons; shared output box.
  • New: click the screen to interact; Apps tab picks from installed apps and shows version; destructive actions in a separate danger area; real Logs, Shell and Files tabs; toasts for results.
Device monitor

Compare devices, then drill in

  • Today: one tall card per device with six big numbers, three progress bars and a tiny unlabeled CPU line; options need an Apply button.
  • New: one row per device with trend lines and warning flags; a hoverable history chart; options apply immediately; CSV export.
Tests · setup

Run Maestro flows on selected phones

  • From the farm: select phones → Run tests. Pick flows (Claude suggests the ones your changes touch); every selected flow runs on every selected phone. Tags, variables, install first.
  • Device checks with fixes; a token limit for Claude's failure diagnosis.
Tests · running

Live progress on each phone

  • Run banner with totals and Cancel; each card shows “Starting Maestro…” (~40 s), then progress, the current flow and its steps, input blocked.
  • Claude classifies failures as they happen: app bug, broken test, flaky test or phone problem, and recovers phone problems.
Tests · results

Grid of flows × phones, with Claude's summary

  • Summary of real failures vs noise, a draft bug report, and a verified flow fix as a diff to apply.
  • Failure screenshot, failed assertion and steps, logcat around the failure, rerun failed, previous runs.
Install APK

See what will change before installing

  • Today: a “page or notification?” prompt first, a preset menu plus checkboxes that overlap, 6 buttons in a row, no APK details.
  • New: APK summary (version, package, size, SDK); device table shows installed version and what will happen; two clear install modes; advanced options folded away; failures explain the fix inline.
